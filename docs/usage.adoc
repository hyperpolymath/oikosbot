= Using OikosBot
:toc:

This guide describes *this source branch*. An existing pinned container may
have older semantics. Do not assume changing `action.yml` documentation upgrades
its image. See link:LAUNCH-READINESS.adoc[release gates and remaining work].

== CLI modes and exit contract

[source,shell]
----
oikosbot analyze src/main.rs --format json
oikosbot report . --format sarif --output results.sarif
oikosbot compare BASE HEAD --format json --output comparison.json
----

* `analyze`: one supported source file, text/JSON/SARIF.
* `report`: a directory, always advisory; default SARIF.
* `check`: directory threshold check. Explicit advisor config makes it advisory;
  absent config, regulator mode or blocking config requests enforcement.
* `compare`: advisory base/head model comparison; `--check` requests enforcement.
  `--pr-body FILE` detects a documentation marker, *not* policy approval.
* `estate`: read-only portfolio telemetry and relative DEA. It never gates.

[cols="1,3",options="header"]
|===
|Exit |Meaning
|0 |Requested analysis/report completed, or an explicitly advisory check completed.
Not proof of sustainability or that an enforcement check passed.
|1 |Supported check returned a negative outcome. Not currently earnable from
per-file resource estimates; retained for future validated inputs.
|2 |No requested check performed: insufficient evidence, empty/excluded/unsupported
input, syntax/read/config error, incomplete collection, invalid format or missing infrastructure.
|===

For a nonblocking review use `report` or `compare` without `--check`. Do not
mask status 2 with `|| true` and then claim a passed gate. JSON and SARIF go to
stdout or `--output`; logs go to stderr. Text also honors `--output`.

*Compatibility change*: previous heuristic `compare --check` warned and exited
0. It now emits its advisory report then exits 2, even when a trade-off heading
exists or the point estimate is unchanged. Old text-only threshold failure was
also format-dependent; gate evaluation now follows rendering for every format.

== Findings, scores and confidence

A finding identifies a *syntactic pattern*, not measured waste. Review semantics
and profile representative useful work before changing it. For example,
`oikosbot/nested-loops` invites algorithm review; a small fixed loop may be correct
and cheap. `busy-wait` suggests checking blocking/event-driven alternatives.
Memory, latency and complexity trade-offs must be evaluated in context.

Eco/Econ/Quality/Overall 0–100 values are heuristic model scores, not percentages
of sustainability or a comparison to a validated world baseline. Overall uses
`0.4*Eco + 0.3*Econ + 0.3*Quality`: inherited value choices, not empirically
justified universal weights. The CLI does not implement arbitrary config weight
overrides. The log-scaled Eco formula can saturate near 100 on tiny table values.
Do not select a launch threshold merely because the score looks precise.

* `Measured`: sourced from observations within a declared boundary, not necessarily
  measuring the intended quantity. Estate wall intervals are API-derived proxies.
* `Calibrated`: requires reproducible calibration against relevant baselines.
  *No per-file table row currently earns this category.*
* `Estimated`: both recognized-pattern tables and naive AST heuristics; estate
  energy, carbon and imputed money also rely on assumptions.
* `Unknown`: no adequate basis supplied.

`resource_range` retains heuristic min/typical/max values. They are not validated
bounds, quantiles or confidence intervals. A named pattern and a wide range do
not constitute calibration. Even the sign of a real-world change remains unverified.

== Pareto verdicts

* *Improvement/regression*: a point vector is no worse on every axis and improves
  by more than tolerance on at least one (or the reverse).
* *TradeOff*: opposing movements; inspect the actual dimensions, not just a score.
* *Neutral*: no modeled movement beyond tolerance, not physical equivalence.
* *Indeterminate*: invalid/missing/non-finite comparison, not a neutral pass.

The CLI aggregates per-function resource proxies and mean quality. These are
not workload-equivalent measurements; adding/removing/splitting functions can
change the comparison. “Optimal” only means nondominated among the supplied
points under this model. It is not global, fair or necessarily feasible.

A `Pareto-Trade-off:` trailer or `Pareto Trade-off` heading records that text is
present. It does not verify substance, approval, consent or an exception to hard
limits. See link:research/EVIDENCE-SCOPED-PARETO.adoc[the separate interval contract]
for a design that retains scope, units, uncertainty, and non-compensatory constraints.
That prototype does not authorize the CLI.

== Finding taxonomy

Pattern findings carry `taxonomy.intent`, `.maintenance`, `.locus` through JSON
and SARIF. The canonical vocabulary is NEUROSYM: `must|intend|wish`,
`corrective|adaptive|perfective|preventive`, `systems|compliance|externalities`.
Current heuristic patterns are `wish/perfective/externalities`. General telemetry
and unclassified synthetic/legacy findings have no taxonomy; do not invent one.

Resource confidence is *not* a probability of correctness. It cannot be mapped
to 0.95 and then used as permission for automatic action. The legacy numeric
Eclexia taxonomy example is not an active runtime rule; auto-action is disabled.

== SARIF

`report --format sarif` emits SARIF 2.1.0 with rule IDs, source locations, messages
and custom properties for scores, resources, confidence, taxonomy, optional bands
and Pareto metadata. Suggestions are text, never invented replacement edits.
`oikosbot/general` is measurement telemetry and is filtered out of alerts; JSON
retains it. Clean analyzed code can therefore yield zero SARIF results without
having zero analyzed units. An empty scan is instead an error.

Upload only when a report file was successfully produced. Full schema and GitHub
consumer validation remain release gates; Rust structural fixtures are not full
SARIF schema validation. Custom properties are for consumers that understand
these limitations, not standardized measured-carbon assertions.

== Configuration

[source,yaml]
----
mode: advisor
thresholds:
  eco_minimum:
    carbon: 50
    enforcement: warning
exclude:
  - "**/target/**"
analysis:
  languages: [rust, javascript, python]
----

`--config` wins over auto-discovery of `.oikos.yml` / `.oikos.yaml` at the directory
root. Excludes match relative paths. Unsupported configured languages, malformed
YAML, unknown modes/enforcement and invalid globs are errors; they no longer
silently broaden a scan. Directory file symlinks are not followed. Fully excluded
or function-free input returns no-check rather than false success.

`eco_minimum.carbon` (or `.energy` fallback) is historically an *Eco-score floor*,
not a physical carbon/energy budget. Do not confuse it with joules/grams. Other
sections of `config/oikos.yaml`, including custom weights and physical budgets,
are target configuration and may be ignored by the current CLI. See
link:policies.adoc[policy implementation boundaries].

`consultant` and `advisor` are advisory config modes. `regulator` requests a
blocking check but does not manufacture evidence. `report` stays advisory in
all modes; `compare --check` is an explicit request independent of these modes.
`BOT_MODE` belongs to the AffineScript App scaffold, not a second CLI mode switch.

== Composite Action

The inputs are declared in link:../action.yml[action.yml]. Pin the Action revision
and the image digest after artifact review. Default mode is advisory `report`,
default format/output are SARIF/`results.sarif`. `compare` requires a base checkout;
use `format: json` and a `.json` output path. The wrapper's legacy SARIF default
for compare is mapped to JSON; it does not provide comparison SARIF.

[source,yaml]
----
- uses: hyperpolymath/oikosbot@REVIEWED_COMMIT_SHA
  with:
    mode: report
    path: .
    format: sarif
    output: results.sarif
----

This is a placeholder example, not an executable pinned workflow. Use a reviewed
published revision, not the literal placeholder. Authentication/package visibility
must be tested independently of local container execution.

== Troubleshooting

* *No check / exit 2*: inspect stderr; distinguish missing evidence from syntax,
  paths, excludes, unsupported languages and tool failures. Use advisory mode
  when advice is what you intended—not an unconditional pass wrapper.
* *GHCR denied*: verify digest availability and anonymous access; no credential
  should be embedded in config or logs. Do not silently fall back to `latest`.
* *No App comment*: the App is not production-ready. Check listener, payload,
  HMAC and transport evidence before assuming the CLI container is a webhook server.
* *Estate partial failure*: retry collection; successful staging is retained.
  Check repository inventory and missing per-repo files before analysis. A capped
  run sample is not a complete history; zero duration can still mean missing time.
* *Surprising score*: inspect raw axes and assumptions, especially AST size and
  quality normalization. Measure equivalent work rather than optimizing the score.

Deployment and containment: link:../DEPLOY.adoc[DEPLOY]. No production App rollout
is recommended until link:LAUNCH-READINESS.adoc[the explicit operational gates] pass.

`--security` currently returns unavailable even with the retained security feature:
the upstream scanner is not integrated. Missing/empty policy directories and
policy evaluation failures also return no-check; they are not clean scans.
