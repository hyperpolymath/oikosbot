= `oikosbot-analysis`

Tree-sitter parsing for Rust, JavaScript and Python, function-level heuristic
resource models, pattern detection and recommendations. Entry points:
`analyze_file`, `analyze_source`, `Analyzer`. Results use `oikosbot-metrics`.
Recovered syntax errors are rejected instead of reporting a partial parse as success.

`patterns.rs` owns the syntactic rules; paired fixtures live in
`tests/pattern_fixtures.rs`. Pattern findings carry the authored taxonomy
`wish/perfective/externalities`; generic measurement telemetry has no taxonomy.

`calibration.rs` is a historical filename for a heuristic operation table. Known
patterns map to operation kinds, returning a min/typical/max envelope. There are
*no reproducible calibration receipts*: all known rows are Estimated; Generic is
Unknown. Unrecognized source uses the naive AST-size heuristic without a band.
The nested-loop/sorting mapping is approximate, not a complexity equivalence.
Neither point estimates nor their envelopes establish physical resource usage.

`carbon.rs` supplies an assumed grid coefficient. `dependencies.rs` performs
manifest analysis. `directives.rs` reads integration directives; `migration.rs`
contains language/migration advice. `security.rs` explicitly returns unavailable:
the retained panic-attack feature has no integrated upstream dependency. It now
compiles as a refusal seam rather than referencing an absent crate.

Tests (require the pinned Rust/native toolchain):

----
cargo test --locked -p oikosbot-analysis --all-features
----

See link:../../docs/LAUNCH-READINESS.adoc[launch gates] before treating any model
output as enforcement evidence. New branch tests still require execution.
